# React with Tailwind, shadcn/ui or Radix

For React apps styled with Tailwind (v3 config or v4 CSS-first `@theme`), components
generated by shadcn/ui into the repo (`components.json`, `components/ui/`), and Radix
primitives. Often with a router, a data-fetching layer and lazy-loaded heavy libraries.

## Before editing

- Read `components.json` (style, aliases, icon library), the CSS entry that defines the
  tokens (`@theme`, `:root`/`.dark` variables), `cn()`/`cva` helpers, and the existing
  `components/ui/` primitives.
- Find the project's data hook (for example one wrapper around TanStack Query) and
  routing mode; new screens follow them.
- Read the project's documented architecture rules (snapshot docs, ADRs) before adding
  files.

## Implementation rules

1. **Primitives first.** Compose from existing `components/ui/*` primitives. Add a new
   shadcn component only with the user's approval, using the project's own CLI and
   config. Generated primitives are project code: edit them deliberately and in one
   place, never by copying a variant into a feature folder.
2. **Tokens through the theme.** Use semantic utilities backed by the theme
   (`bg-background`, `text-muted-foreground`, `border-border`). A raw palette class
   (`bg-blue-500`) or arbitrary value (`p-[13px]`) needs a reason; a repeated one
   becomes a token via `ui-design-system`.
3. **Variants via `cva`.** Express visual variants as `cva` variants on the component;
   merge caller classes with `cn()` last so overrides stay predictable. Avoid boolean
   prop modes; see [react-rules.md](react-rules.md).
4. **Radix behaviour stays intact.** Keep `asChild`, focus management, portal and
   `Dialog`/`Popover` structure; do not re-implement keyboard handling Radix provides.
   Dialogs keep a title (visually hidden if needed) and description.
5. **Dark mode and direction.** Use the project's theme mechanism (class or
   `data-theme`). Prefer logical utilities (`ms-*`, `me-*`, `ps-*`, `start-*`) and the
   `rtl:` variant only where logical utilities cannot express it.
6. **Performance.** Keep heavy libraries (charts, editors, highlighters, graphs)
   lazy-loaded the way the project already does; do not import them into a shared entry
   chunk. Respect any existing manual chunking.
7. **Motion.** Use the project's motion library and its reduced-motion handling; add
   no new animation dependency.

## Verify

Run the project's build (it type-checks with `tsc -b` in many setups) and lint. Then the
visual loop in both themes and at phone width; open each Radix overlay with the keyboard
and close it with Escape. A Tailwind class that compiled is not evidence that it
rendered: look.
